# 软件工程 Chapter 9 实现技术

## 第九章核心定位与逻辑脉络

### 核心定位

实现技术是**设计落地为可运行软件的关键支撑**——在第五章类设计、第七章详细设计、第八章设计优化的基础上，通过“数据处理、复用技术、持久化、模型驱动、重构”等核心技术，将抽象设计转化为具体代码，同时满足第三章的功能性与非功能性需求（如性能、安全、可维护性），是“设计→编码→运行”的桥梁。

### 核心逻辑链

本章遵循“**基础需求→数据处理→复用技术→持久化→高级技术→代码优化**”的流程：

```
前序设计（类/详细设计/优化）→ 非功能性需求实现（性能/安全）→ 数据交换格式（XML/JSON/YAML）→ 复用技术（类库/组件/框架）→ 数据持久化（文件/数据库）→ 高级实现技术（DSL/MDA）→ 代码重构→ 落地可运行软件
```

核心目标：用工程化的技术手段，高效、高质量地将设计转化为代码，兼顾复用性、可维护性和扩展性。

## 非功能性需求的实现：不止于功能，更要重质量

实现阶段不仅要满足第三章的功能性需求，更要落地非功能性需求（性能、安全、可测试性等），这些需求直接决定软件的用户体验和稳定性。

### 1. 核心非功能性需求及实现方式

| 非功能性需求类型 | 核心要求 | 实现方式（硬件+软件） | 关联前序章节 |
| :---: | :---: | :---: | :---: |
| 性能需求（响应速度、并发） | 低延迟、高吞吐量 | 硬件：高性能服务器、负载均衡器；软件：优化算法、缓存机制、分布式架构 | 第四章架构设计（C/S/B/S）、第八章策略模式（算法优化） |
| 安全需求（传输/数据/操作安全） | 防入侵、数据加密、权限控制 | 传输安全：HTTPS协议；数据安全：数据加密存储；操作安全：权限校验、防注入攻击 | 第三章非功能性需求、第五章边界类（权限控制界面） |
| 可测试性需求 | 便于单元测试、集成测试 | 软件结构模块化（高内聚低耦合）、接口标准化、方法逻辑简洁 | 第七章结构化程序设计（单入口/单出口）、第八章单一职责原则 |
| 健壮性需求（容错、抗干扰） | 避免崩溃、异常可恢复 | 异常处理机制、输入校验、降级策略 | 第七章PDL中的异常处理、第六章代码框架的容错设计 |

### 2. 典型架构示例：负载均衡架构

为满足高并发、高可用的性能需求，常见架构为“负载均衡器+多Web服务器+应用服务器+读写分离数据库”，核心作用：

- 负载均衡器分发请求，避免单点压力过大；

- 读写分离数据库（Read/Write分离）提升数据访问效率；

- 缓存层减少数据库查询压力，缩短响应时间。

## 数据表示与交换格式：系统间的“沟通语言”

数据交换格式用于系统内部模块、系统与外部系统的数据传输，需兼顾可读性、简洁性和兼容性，核心有三种主流格式，需根据需求选择。

### 1. 三种核心格式对比（优缺点+适用场景）

| 格式类型 | 核心特点 | 优势 | 劣势 | 适用场景 |
| :---: | :---: | :---: | :---: | :---: |
| XML（可扩展标记语言） | 结构化强、支持自定义标签、有DTD/XSD校验 | 可读性强、标准化程度高、适合复杂数据结构 | 语法复杂、文件体积大、解析效率低 | 配置文件、跨平台复杂数据交换（如企业级系统接口） |
| JSON（JavaScript对象表示法） | 轻量级、基于键值对、支持嵌套/数组 | 语法简洁、解析速度快、Web端原生支持 | 不支持注释（旧版本）、复杂校验需额外处理 | Web应用、移动应用接口、轻量级数据交换（如前后端分离项目） |
| YAML（另一种标记语言） | 缩进表示层次、支持注释、兼顾可读性与简洁性 | 人类可读性强、配置文件友好、支持复杂数据类型 | 缩进敏感（易出错）、解析效率中等 | 配置文件（如Docker-compose.yml、Spring Boot配置） |

### 2. XML的处理方式（DOM vs SAX）

XML解析是实现数据交换的关键，两种核心处理方式适配不同场景：

| 处理方式 | 核心逻辑 | 优势 | 劣势 | 适用场景 |
| :---: | :---: | :---: | :---: | :---: |
| DOM（文档对象模型） | 加载整个XML文档到内存，构建树形结构 | 支持随机访问、可修改文档内容 | 内存占用大、解析速度慢 | 复杂XML文档、需要频繁修改/查询数据的场景 |
| SAX（简单API for XML） | 流式解析，逐节点读取，不加载整个文档 | 内存占用小、解析速度快 | 仅支持读取、无法随机访问 | 大型XML文档、仅需提取特定数据的场景（如日志解析） |

### 3. 关键补充：XML的有效性

- 符合DTD/XSD约束的XML文档称为“well formed”（格式良好），确保数据结构规范；

- DTD/XSD定义了XML的标签、属性、数据类型规则，是系统间数据交换的“契约”，避免数据格式不一致。

## 程序轮子：复用技术的三层境界（类库→组件→框架）

“轮子”是前人验证过的成熟解决方案，复用轮子可大幅提升开发效率，避免重复造轮子，按复用粒度分为类库、组件、框架三层，层层递进。

### 1. 三层复用技术对比

| 复用类型 | 核心定义 | 核心特征 | 示例 | 关联前序章节 |
| :---: | :---: | :---: | :---: | :---: |
| 类库（函数库/类库） | 封装单一功能的函数或类集合 | 被动调用（开发者控制流程）、松耦合、按需使用 | Java的ArrayList、Math类，C++的STL | 第五章类设计（复用类的属性/方法）、第八章合成复用原则 |
| 组件（Component） | 封装子应用的独立模块，含数据+方法+接口 | 可配置、支持拖放式编程、设计时态+运行时态 | Java Bean、Swing控件（JButton/JTable） | 第五章边界类（界面组件）、第八章观察者模式（组件通讯） |
| 框架（Framework） | 半成品系统，提供通用平台和接口，嵌入业务类 | 控制权反转（框架调用业务类）、强约束、整体复用 | Java的Swing TreeModel、Spring框架 | 第四章架构设计（MVC框架）、第八章设计模式（组合使用） |

### 2. 组件的深度解析（以Java Bean为例）

组件是类库的升级，核心是“即插即用”，Java Bean是Java领域的标准组件，需遵循以下规则：

- 必须有默认无参构造函数；

- 实例变量需提供get/set方法（属性访问）；

- 可实现Serializable接口（支持序列化，便于存储和传输）；

- 组件通讯：通常采用观察者模式（如Java Bean的事件监听机制），呼应第八章的行为模式。

#### 组件的两种时态

- 设计时态：在可视化编辑器中配置属性（如设置JButton的文字、颜色），不执行方法；

- 运行时态：嵌入应用程序，响应事件、与其他组件协同工作（如点击按钮触发数据查询）。

### 3. 框架的核心：控制权反转（IoC）

框架与组件的核心区别是“控制权转移”：

- 组件：开发者调用组件方法（开发者控制流程）；

- 框架：框架定义流程，开发者通过实现接口/继承类嵌入业务逻辑（框架控制流程）。

#### 示例：Java Swing的TreeModel框架

- 框架提供TreeModel接口（定义树结构的核心方法：getChild、getRoot等）；

- 开发者实现TreeModel接口（如ProjectTreeModel），嵌入项目管理的业务逻辑（关联ProjectMan类）；

- 框架调用实现类的方法，展示树状结构，开发者无需关注界面渲染细节。

## 数据持久化：实体类的“永久存储”

数据持久化是将第五章的实体类（如Project、Employee）的数据永久保存（文件/数据库），解决“内存数据易丢失”的问题，核心分为两种方式。

### 1. 两种持久化方式对比

| 持久化方式 | 实现方式 | 优势 | 劣势 | 适用场景 |
| :---: | :---: | :---: | :---: | :---: |
| 文件持久化 | 二进制文件、XML/JSON文件，Java中需实现Serializable接口 | 实现简单、可读性（文本文件）、无需数据库环境 | 二进制文件不可读、类结构变化后无法兼容、不支持并发访问 | 小型应用、临时数据存储、简单配置文件 |
| 数据库持久化 | 关系型数据库（Oracle/MySQL）、ORM框架（Hibernate/MyBatis） | 支持并发访问、数据一致性强、查询高效、可扩展 | 需设计数据库表、存在“阻抗失配”问题 | 中大型应用、大数据量存储、多用户共享数据 |

### 2. 关键技术点解析

#### （1）文件持久化：Serializable接口

- 作用：Java中标记类可序列化，允许对象以二进制形式存储到文件；

- 要求：类的所有实例变量、静态变量的类型也需实现Serializable；

- 问题：类结构变化（如新增属性）后，旧文件无法反序列化，需编写转换程序。

#### （2）数据库持久化：解决“阻抗失配”

- 阻抗失配：实体类的“对象模型”（如继承、关联）与数据库的“关系模型”（表、字段）不兼容；

- 解决方案：ORM（对象关系映射）工具（如Hibernate），自动完成对象与表的映射（属性→字段、类→表、关联→外键）；

- 价值：开发者无需关注SQL编写，专注业务逻辑，呼应第一章“高效开发”原则。

## 高级实现技术：DSL与模型驱动架构（MDA）

### 1. 领域特定语言（DSL）：领域的“专属语言”

#### 核心定义

DSL是针对特定领域的受限表达语言，不依赖通用编程语言，核心价值是“清晰沟通+平台无关”。

#### 分类与特点

| DSL类型 | 核心定义 | 实现方式 | 优势 | 示例 |
| :---: | :---: | :---: | :---: | :---: |
| 内部DSL | 基于通用语言的特定用法（如Java编写的业务指令） | 借助通用语言的语法，封装领域指令 | 无需新语言学习、开发成本低 | 用Java编写的“菜单配置DSL”：`Menu("Data", "Load", "Save")` |
| 外部DSL | 独立于通用语言的全新语言 | 自定义语法、编写解析器 | 表达更精准、领域适配性强 | SQL（数据库领域）、HTML（网页领域） |

#### 核心价值

- 改善沟通：领域专家与开发者用同一语言交流，减少需求偏差（关联第三章需求分析的沟通挑战）；

- 平台无关：同一DSL可适配不同实现平台（如Java/.NET），提升可移植性（关联第二章的可移植性需求）。

### 2. 模型驱动架构（MDA）：模型→代码的自动化

#### 核心思想

MDA是“与编程语言、架构无关”的开发方法，通过模型转换实现自动化编码，核心是“模型驱动而非代码驱动”。

#### 四个核心阶段（从抽象到具体）

| 阶段 | 核心定位 | 示例（PowerDesigner数据库设计） | 关联前序章节 |
| :---: | :---: | :---: | :---: |
| CIM（计算无关模型） | 聚焦需求与环境，不涉及系统内部结构 | 数据库概念模型（CDM）：描述实体关系（如学生-选课-课程） | 第三章需求分析、第四章架构的全局视图 |
| PIM（平台无关模型） | 聚焦系统内部细节，不依赖具体技术平台 | 数据库逻辑模型（LDM）：定义字段类型（如学号为CHAR(8)） | 第五章类设计、第八章设计模式 |
| PSM（平台特定模型） | 适配具体技术平台（如Oracle、J2EE） | 数据库物理模型（PDM）：映射Oracle字段类型（CHAR→VARCHAR2） | 第四章架构的物理视图、第六章代码生成 |
| 编码（Coding） | 工具自动将PSM转换为代码 | 生成Oracle建表SQL语句 | 第六章代码生成、第七章详细设计 |

#### 核心优势

- 自动化转换：模型转换由工具完成，减少手动编码错误；

- 模型复用：同一PIM可转换为多个PSM（如适配不同数据库），提升复用性（关联第八章的合成复用原则）；

- 文档与代码一致：模型即文档，避免文档与代码脱节（关联第一章“结果可审查”原则）。

## 重构：代码层面的“优化收尾”

重构是实现阶段的代码优化，核心是“在不改变功能的前提下，简化代码、提升可读性和可维护性”，聚焦方法级优化。

### 1. 重构的核心准则（方法级）

- 方法名自解释：无需注释即可理解功能（如`computeProjectCompletePct()`而非`func1()`）；

- 方法长度控制：最长不超过12行，避免复杂嵌套（if/while/switch嵌套不超过2层）；

- 逻辑单一：一个方法仅完成一个功能（呼应第八章单一职责原则）。

### 2. 重构示例（方法拆分）

#### 重构前（复杂方法）

```java
public int ref2(int x) {
    int a=0, b=0, c=0;
    if(x>0) {
        a=x;
        b=x;
        c=x;
    }
    return a+b+c;
}
```
#### 重构后（拆分辅助方法）

```java
public int ref2(int x) {
    int a=0, b=0, c=0;
    if(x>0) {
        abcModify(a, b, c, x); // 辅助方法封装赋值逻辑
    }
    return a+b+c;
}
private void abcModify(int& a, int& b, int& c, int x) {
    a=x;
    b=x;
    c=x;
}
```

### 3. 核心价值

- 降低维护成本：简洁代码便于后续修改（关联第一章“可维护性”目标）；

- 提升可测试性：方法逻辑单一，单元测试更易覆盖（关联第二章的可测试性需求）；

- 衔接第八章优化：重构是设计优化在代码层面的落地，呼应“小即是美”理念。
